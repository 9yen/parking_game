# 《一起停车吧》视觉规格

- 版本：`v0.1`
- 状态：讨论稿
- 核心方向：斜俯视 2.5D + 现代像素卡通 + 桌面伴侣

## 1. 视觉目标

玩家应能在小窗口中迅速看懂：哪些车位为空、哪辆车属于谁、已经停了多久、当前收益是否达到上限。视觉首先服务信息清晰和放松氛围，其次才是写实程度和复杂动画。

关键词：可爱、清晰、温暖、轻松、办公室陪伴、略带怀旧但不陈旧。

## 2. 视角与构图

- 使用类似经典社交停车游戏的斜俯视 2.5D 舞台视角。
- 玩家同时看到车顶、车身侧面和完整停车场。
- 不采用严格正上方俯视，也不要求严格等距投影。
- 主停车场固定展示 4 个清晰车位。
- 车位位置和主要交互区域在所有主题中保持一致。
- 场景主题只替换地面、围栏、建筑、植物、天气、灯光和装饰，不能改变点击规则。

## 3. 美术风格

选择“现代像素卡通”，而非粗糙复古大像素：

- 场景、车辆和环境动画采用统一像素网格与受控色板。
- UI 使用清晰、圆润的现代卡通界面。
- 正文不使用难读的装饰像素字体。
- 宣传图可以使用更细腻的插画，但必须忠实呈现游戏内风格。
- 油画或厚涂只用于宣传、主题背景或特殊收藏插画，不作为主要批量资产形式。

在确定像素密度、参考分辨率和导入过滤规则后，所有资产必须遵守同一标准；不得逐个资产随意缩放导致像素大小不一致。

## 4. 初始停车场主题

默认主题为“晴日下午的创意园区写字楼后院”：

- 四车位地面停车场。
- 玻璃或浅色外墙办公楼作为背景。
- 绿化花坛、路灯、保安亭、自动售货机和外卖架。
- 整体干净、温暖，带一点上班日常幽默感。
- 避免灰暗封闭的大型地下车库观感。

后续主题可包含雨夜写字楼、住宅小院、海滨停车场、雪地车场、复古商业街和未来城市。主题通过成长、活动、转生、成就或纯外观内容获得。

## 5. 车辆设计

- 所有车辆均为虚构车款，不使用真实品牌、车标、车型名或受保护造型细节。
- 采用“七分真实、三分可爱”的比例。
- 相比真实汽车，车身长度缩短约 15%～20%，车窗和车轮略大。
- 保留小型车、轿车、SUV、跑车和面包车等明显轮廓。
- 颜色鲜明但不刺眼；车辆在晴天、夜晚和雨天都必须易识别。
- 轮毂、尾翼、车灯、车漆和贴纸等改装在小窗口中也要看得出来。
- 不依赖细小文字或真实车牌表达稀有度。

每款车辆至少需要：

- 停放主视角精灵。
- 进入和返回所需的表现精灵或可复用动画方案。
- 缩略图或车库列表图标。
- 轮廓遮罩、染色区域或等价的可改装数据。
- 选中、不可用、外出中和收益已满的 UI 状态。

## 6. 停车动画

停车采用“立即确认 + 短表现动画”：

1. 点击空车位后立即锁定业务状态。
2. 车辆从画面入口沿预设短路径驶入。
3. 约 0.6～1 秒完成停车。
4. 播放轻微引擎、刹车和成功反馈。

动画不进行碰撞、真实物理或动态寻路。紧凑小窗、批量操作和“减少动态效果”模式允许缩短或跳过动画。联机版本中，服务器确认优先于动画；动画失败不得回滚已确认经济状态。

## 7. 人物与停车场身份

MVP 不在停车场内显示完整可行走的好友人物：

- 画面顶部显示停车场名称、头像、等级和主题。
- 固定 NPC 使用像素头像、短名称、职业图标和一句简短介绍。
- 场景可以包含办公室窗户剪影、保安亭值班等非交互环境动画。
- 完整玩家形象、车手或车旁展示人物属于后续收藏系统。

NPC 名称原则：

- 使用稳定内部 ID，如 `npc_mina`。
- 显示名称短、容易发音；职业和介绍完整本地化。
- 名称不承担关键规则说明。
- 不使用依赖单一语言谐音、网络梗或文化刻板印象的关键笑点。

## 8. 昼夜与天气

MVP 包含：

- 缓慢的游戏内昼夜循环。
- 晴天、阴天和小雨三种基础天气，最低交付可先完成晴天与小雨。
- 可分别调节音乐、环境音和天气音量。

正式版提供：

- 自动循环。
- 跟随电脑本地时间。
- 锁定早晨、白天、黄昏或夜晚。
- 模拟天气、手动天气和天气锁定。

后期可选真实天气：

- 必须由玩家主动开启。
- 只使用城市级粗略位置，不请求精确定位。
- 断网或服务失败时自动退回模拟天气。
- 真实时间和天气原则上只改变视觉、环境音和极小趣味事件。
- 不降低停车收益，不影响排行榜公平。

## 9. 窗口模式

- 普通可缩放窗口：用于车库整理、改装、图鉴和设置。
- 紧凑小窗：放在屏幕角落或边缘，用于查看停车状态和快速操作。
- 全屏可支持，但不是产品主要卖点。

MVP 先完成普通窗口和紧凑小窗。置顶、屏幕边缘吸附、透明背景、点击穿透和会议保护模式属于后续平台功能，必须分别验证 Windows、macOS 和 Linux 行为。

紧凑小窗中必须保留：

- 四车位状态或等价精简视图。
- 当前金币和待领取报告提示。
- 快速召回与重新派车入口。
- 返回普通窗口的明确按钮。

## 10. UI 与反馈

- 空车位、已占用、自己车辆、好友车辆和 NPC 车辆必须有形状或图标差异，不能只靠颜色。
- 金币、经验、停车时长和收益上限使用一致图标。
- 数字增长使用短暂而克制的跳字或光点，不遮挡车辆。
- 离线报告应先给总结果，再允许展开每辆车明细。
- 重要操作必须提供撤销、确认或明确后果；普通高频停车不弹出多余确认框。
- Steam 名称属于外部输入，必须限制显示长度并处理特殊字符。

## 11. 搞笑停车贴纸

- 贴纸视觉可爱、轻松，不模拟严厉政府罚单。
- 每张贴纸使用稳定事件 ID 和本地化文本。
- 贴纸可以有不同主题边框、图标和收藏等级。
- 文案不羞辱玩家，不使用地区政治、歧视或难以翻译的梗。
- 默认互动包括点赞、鸣笛、送咖啡、打招呼和请离。

## 12. 声音与音乐

- 主音乐方向为轻柔 Lo-fi、暖色电子或低强度爵士元素。
- 音乐适合长时间循环，不含突然的大音量变化。
- 环境音包括远处车流、鸟叫、办公室空调感、雨声和夜间虫鸣。
- 操作音短促、柔和；金币反馈不连续轰炸。
- 音乐、环境、天气和 UI 音效可分别调节或静音。
- 失焦或后台运行时提供降低音量或完全静音选项。

## 13. 本地化与无障碍

- MVP 文本语言为简体中文和英语。
- 所有玩家可见文本使用本地化键，不硬编码在场景或业务脚本中。
- UI 为德语等较长文本预留至少 30% 扩展空间。
- 字体覆盖拉丁、简繁中文和常用符号；后续语言按需增加字形。
- 时间、数字和复数使用可本地化格式。
- 支持可调文字大小、减少动态效果、独立音量和色觉友好表达。
- 语言测试必须覆盖文本溢出、截断、缺字和从右到左语言的未来兼容风险。

## 14. 性能目标

- 桌面伴侣模式应保持低 CPU、GPU 和内存占用。
- 失焦或无交互时允许降低刷新率和动画更新频率。
- 天气粒子数量按窗口大小与性能设置缩放。
- 经济计时使用时间差计算，不依赖每帧累加。
- 禁止为了挂机收益要求窗口持续高帧率运行。

## 15. 视觉验收问题

每次新增车辆、主题或 UI 前检查：

1. 在最小支持窗口中能否分辨车辆和车位状态？
2. 夜晚和雨天是否仍能看清交互目标？
3. 是否误用了真实品牌、车标或明显受保护设计？
4. 动画能否被跳过且不改变业务结果？
5. 中英文是否均无溢出和缺字？
6. 信息是否依赖颜色才能理解？
7. 新资产是否遵守统一像素密度、轮廓和色板？

## 16. 视觉参考

- 经典社交停车游戏：参考斜俯视舞台和清晰车位信息，不复制名称、美术和数值。
- [Rusty's Retirement](https://store.steampowered.com/app/2666510/)：参考桌面常驻、小窗口与现代像素氛围。
- [Gourdlets](https://store.steampowered.com/app/2013730/)：参考闲置窗口、主题布置、昼夜与可控天气。
- [Mini Motorways](https://store.steampowered.com/app/1127500/)：参考交通元素的简洁轮廓、色彩和小尺寸可读性。
